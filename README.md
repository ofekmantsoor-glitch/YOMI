# yomi

אפליקציה שמחברת בין פגישות טיפול CBT לבין מה שקורה בחיי המטופל בין הפגישות.

פרויקט בקורס נתונים וטכנולוגיה בעסקים.

## הרעיון בקצרה

בטיפול CBT חלק גדול מהעבודה קורה בין הפגישות, אבל המטפל לא רואה מה קרה, והמטופל נשאר לבד עם הכלים.

- **המטופל** (בטלפון) רואה את המשימות שהמטפל הגדיר ומדווח עליהן סמוך לביצוע. אפשר לדווח גם על משימה שלא בוצעה, ולתעד ניטור מחשבות גם ביוזמה אישית.
- **המטפל** (במחשב) מגדיר משימות בפגישה, ולקראת הפגישה הבאה רואה את השבוע של המטופל בתצוגה שבועית.

בגרסה הראשונה יש שני סוגי משימות: **ניטור מחשבות** (מצב, רגש ומחשבה) ו**משימה התנהגותית או חשיפה**.

האפליקציה לא מפרשת, לא מאבחנת ולא משתמשת ב-AI, ואינה שירות חירום.

## מצב הפרויקט

שלב עיצוב. עדיין אין קוד, ולא נקבעו טכנולוגיות.

התוצרים הקרובים:

1. מפת מסכים לשני התפקידים.
2. תרשימי מסכים ראשוניים (Wireframes).
3. אבטיפוס לחיץ.

## עבודה עם האפיון

- האפיון מבחין בין **החלטות שהתקבלו**, **הצעות** ו**החלטות פתוחות**. שומרים על ההבחנה: לא מציגים הצעה כהחלטה, ולא סוגרים החלטה פתוחה בלי הסכמה בצוות.
- החלטה חדשה מתעדכנת קודם ב-`docs/spec.md`, ורק אחר כך ב-`CLAUDE.md`.
- יש גרסה אחת בלבד של האפיון, בלי עותקים מקבילים.
- כל הנתונים בתוצרים הם **נתוני הדגמה בדויים**. אין להכניס למאגר מידע אמיתי של מטופלים.

## איך מתחילים לעבוד

מורידים את המאגר:

```bash
git clone https://github.com/ofekmantsoor-glitch/YOMI.git
```

לפני כל עבודה מושכים את העדכונים של שאר הצוות:

```bash
git pull
```

אחרי שינוי שומרים ומעלים:

```bash
git add -A
git commit -m "תיאור קצר של השינוי"
git push
```

כדי לצמצם התנגשויות: עובדים בקומיטים קטנים, דוחפים לעיתים קרובות, ומתאמים מראש כשכמה אנשים עורכים את אותו קובץ, במיוחד את `docs/spec.md`.
