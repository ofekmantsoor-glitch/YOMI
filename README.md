# yomi

אפליקציה שמחברת בין פגישות טיפול CBT לבין מה שקורה בחיי המטופל בין הפגישות.

פרויקט בקורס נתונים וטכנולוגיה בעסקים.

## הרעיון בקצרה

בטיפול CBT חלק גדול מהעבודה קורה בין הפגישות, אבל המטפל לא רואה מה קרה, והמטופל נשאר לבד עם הכלים.

- **המטופל** (בטלפון) רואה את המשימות שהמטפל הגדיר ומדווח עליהן סמוך לביצוע. אפשר לדווח גם על משימה שלא בוצעה, ולתעד ניטור מחשבות גם ביוזמה אישית.
- **המטפל** (במחשב) מגדיר משימות בפגישה, ולקראת הפגישה הבאה רואה את השבוע של המטופל בתצוגה שבועית.

בגרסה הראשונה יש שני סוגי משימות: **ניטור מחשבות** (מצב, רגש ומחשבה) ו**משימה התנהגותית או חשיפה**.

האפליקציה לא מפרשת, לא מאבחנת ולא משתמשת ב-AI, ואינה שירות חירום.

## מצב הפרויקט

בונים את ה-MVP לפי [docs/prd.md](docs/prd.md). השלב הנוכחי הוא שלב 1, הקמה.
הטכנולוגיה (React, TypeScript, Tailwind ו-Supabase) היא הצעת ה-PRD, ועדיין מחכה לאישור הצוות.

## הרצה מקומית

צריך Node 22 ומעלה. **את המאגר משכפלים מחוץ ל-Google Drive**, כי Drive משבש את git ואת `node_modules`.

```bash
npm install
cp .env.example .env.local   # למלא את הפרטים מ-Supabase → Project Settings → API
npm run dev                  # http://localhost:5173, וגם מהטלפון באותה רשת
npm test                     # לוגיקת השבוע ובדיקות ההרשאות על עותק מקומי של מסד הנתונים
npm run e2e                  # תרחיש הקבלה וכללי המוצר בדפדפן (פעם ראשונה: npx playwright install chromium)
```

**מצב הדגמה מקומי (כרגע ברירת המחדל):** האפליקציה רצה בלי שרת, עם נתוני הדגמה בדויים שנשמרים רק בזיכרון ונמחקים ברענון הדף.
- מטפל: `/therapist`. נכנסים עם `therapist1@yomi.test` או `therapist2@yomi.test`, סיסמה `demo1234`.
- מטופל: `/`. מצטרפים עם קוד שהמטפל יוצר.
- בתחתית כל מסך יש "כלי הדגמה": מעבר בין התפקידים, כניסה ישירה כמטופל הדגמה, והדמיה של כשל בשמירה.

הקמת Supabase חד-פעמית: להריץ את `supabase/migrations/001_schema.sql` ב-SQL Editor, ולהפעיל את Authentication → Anonymous sign-ins.
אחר כך מריצים `npm run demo:reset`. הפקודה מוחקת את כל הנתונים וטוענת נתוני הדגמה בדויים, ולכן צריך `SUPABASE_SERVICE_ROLE_KEY` ו-`DEMO_PASSWORD` ב-`.env.local`.

## עבודה עם האפיון

- האפיון מבחין בין **החלטות שהתקבלו**, **הצעות** ו**החלטות פתוחות**. שומרים על ההבחנה: לא מציגים הצעה כהחלטה, ולא סוגרים החלטה פתוחה בלי הסכמה בצוות.
- החלטה חדשה מתעדכנת קודם ב-`docs/spec.md`, ורק אחר כך ב-`CLAUDE.md`.
- יש גרסה אחת בלבד של האפיון, בלי עותקים מקבילים.
- כל הנתונים בתוצרים הם **נתוני הדגמה בדויים**. אין להכניס למאגר מידע אמיתי של מטופלים.

## איך מתחילים לעבוד

מורידים את המאגר:

```bash
git clone https://github.com/ofekmantsoor-glitch/YOMI.git
```

לפני כל עבודה מושכים את העדכונים של שאר הצוות:

```bash
git pull
```

אחרי שינוי שומרים ומעלים:

```bash
git add -A
git commit -m "תיאור קצר של השינוי"
git push
```

כדי לצמצם התנגשויות: עובדים בקומיטים קטנים, דוחפים לעיתים קרובות, ומתאמים מראש כשכמה אנשים עורכים את אותו קובץ, במיוחד את `docs/spec.md`.
